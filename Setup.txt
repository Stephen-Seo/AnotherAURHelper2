================================================================================
    Setup
================================================================================

This document has notes on how to set up the environment for AnotherAURHelper2.

Requires an installation of ArchLinux using btrfs as the main filesystem
(without btrfs, using "temporary clones" of the chroot will be more expensive).
May also require a sane cache for packages if you are using multiple x86_64 Arch
installations.

Note that the container will be referred to as "the chroot", but will be mostly
handled by systemd-nspawn and machinectl.

--------------------------------------------------------------------------------
    Notes about this Guide
--------------------------------------------------------------------------------

Lines starting with ">" are commands to run on the host.
Lines starting with "$" are commands to run in the chroot.

--------------------------------------------------------------------------------
    Dependencies
--------------------------------------------------------------------------------

The package arch-install-scripts is requried to create the chroot.

--------------------------------------------------------------------------------
    Important things to know
--------------------------------------------------------------------------------

By default, anotherAurHelper2.py causes heavy use of your pacman mirrors.
Consider setting up a local private mirror so that you don't constantly
download from a remote mirror (Check the arch wiki).
https://wiki.archlinux.org/title/Package_proxy_cache

Alternatively, follow the guide (in the latter end) to expose the host's pacman
cache to the container.

If you don't have much RAM, then you probably should have:

build_in_tmpfs = false

...in your config. This option will fetch and build into RAM if enabled. Having
at least 64GiB would be ideal.

The main log file specified by "log_file" in the config, and the per-pacakge
logs logged into the "logs_dir" (also specified in the config) should be handled
properly, otherwise some disk space may be wasted storing old log files that may
be long. It is recommended to use a program like "logrotate" on the HOST to
periodically clear up log files.

--------------------------------------------------------------------------------
    The Container
--------------------------------------------------------------------------------

Go to /var/lib/machines and create a btrfs subvolume (or a regular directory for
those not using btrfs) with the name "aurbuild" (or another name, but you must
remember that you changed the name as this guide will use the name "aurbuild"
repeatedly).

> btrfs subvolume create /var/lib/machines/aurbuild
> pacstrap /var/lib/machines/aurbuild base base-devel vim openssh git cmake ninja meson nftables rsync

You may replace "vim" with another terminal-based editor of choice (like nano).

From now on, start the container with `machinectl start aurbuild` and stop it
with `machinectl poweroff aurbuild`. You may get a root shell immediately if
needed with `machinectl shell root@aurbuild`. It is highly recommended to set a
password for the root user and to harden the system (strict sudo/su/policykit,
etc).

Set up some stuff that usually occurs when installing an Arch system from
scratch (locale.gen, hostname, etc).

Create a 'aur' user in the container with `useradd -m -s /bin/bash aur`, and set
the password for this user.

Also ensure 'aur' is "wheel" and that the sudoers file allows users in "wheel".
Also ensure that the build user ("aur") can install packages without prompting
for the password. (This is optional):

$ gpasswd -a aur wheel
$ EDITOR=vim visudo

...
# allows wheel to use sudo
%wheel ALL=(ALL:ALL) ALL

# allows wheel to run the following "pacman" commands without a password
%wheel ALL=(ALL:ALL) NOPASSWD: /usr/bin/pacman -S *
%wheel ALL=(ALL:ALL) NOPASSWD: /usr/bin/pacman --noconfirm -S *
%wheel ALL=(ALL:ALL) NOPASSWD: /usr/bin/pacman -Sy *
%wheel ALL=(ALL:ALL) NOPASSWD: /usr/bin/pacman --noconfirm -Sy *
%wheel ALL=(ALL:ALL) NOPASSWD: /usr/bin/pacman -U *
%wheel ALL=(ALL:ALL) NOPASSWD: /usr/bin/pacman --noconfirm -U *
...


You must set up networking by either host networking mode or forwarding as
mentioned here: https://wiki.archlinux.org/title/Systemd-nspawn#Networking
You must also set up sshd and access to the container by the user. By the end of
setting up the network and sshd, you should be able to ssh into the 'aur' user
and be able to use sudo.

See the configExamples/ directory for systemd service file examples for setting
up ip addresses with the default networking setup. Note that this also requires
setting up forwarding with the firewall.

Test that you actually have access to the network by installing a package or
using curl.

Enable [multilib] by editing /etc/pacman.conf and doing a quick `pacman -Syu` in
the container.

Ensure that the chroot systemd timeout time is short so that shutting down the
container doesn't hang for the default 90 seconds (edit
/etc/systemd/system.conf in the chroot):

[Manager]
...
DefaultTimeoutStopSec=10s
...

Stop the container before the next step:
Add the following text snippet to /etc/systemd/nspawn/aurbuild.nspawn :

[Exec]
Ephemeral=on

[Files]
TemporaryFileSystem=/tmp:rw,nodev,nosuid,size=98%

This config will cause all future starts of the container to be a clone of the
original container and when the container is stopped, the clone is erased. In
other words, the container becomes immutable and every time it is started with
this config option set, a temporary copy is used instead. If the container is
inside of a btrfs subvolume, creation of the copy should be fast.

Note that if you want to update the container, you must set "Ephemeral" to "off"
and start the container afterwards for changes to persist. Don't forget to set
it back to "on" after you've powered off the container with your changes.


TO REDUCE PACMAN PKG DOWNLOADS THOUGH IT EXPOSES THE ROOT PKG CACHE TO CONTAINER

Add to "/etc/systemd/nspawn/aurbuild.nspawn" :

[Files]
...
Bind=/var/cache/pacman/pkg:/var/cache/pacman/pkg:owneridmap
...

Also, edit "/etc/pacman.conf" in the CONTAINER and comment out the following
line:

#DownloadUser = alpm

These two changes will cause the container to use the host's pacman cache.


If one wants as much as possible in the tmpfs (RAM), the option:

build_in_tmpfs = false

...in the config puts the build into /tmp in the container.

Also, consider:

[Files]
Volatile=overlay

...to make filesystem changes in the container to also be put into the temporary
file system.
WARNING: You must set "Volatile=no" and "Ephemeral=no" if you want to update the
container, and change it back after powering it off.
